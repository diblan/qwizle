# Design Docs

Design docs explain important technical or product design decisions before they become implementation work. They should describe the problem, the chosen direction, rejected alternatives when useful, and the consequences of the decision.

Current design docs:

- `core-beliefs.md` — the practical engineering beliefs that guide Qwizle changes.

For complex features or significant refactors, write an ExecPlan in `docs/exec-plans/` and follow `PLANS.md`. ExecPlans are living implementation plans; design docs are durable decision records and orientation notes.
