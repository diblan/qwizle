# Qwizle Documentation Index

The `docs/` directory is the durable knowledge base for Qwizle. It is written for both humans and AI agents so future work can start from checked-in context instead of memory, chat history, or external articles.

`AGENTS.md` is the short repository entry point. Use it to orient yourself, then read the focused documents below for the decision area you are touching.

## Product and Planning

- `docs/product-specs/index.md` lists current product specifications.
- `docs/product-specs/product-vision.md` explains the product goal, current slice, and explicit non-goals.
- `docs/product-specs/daily-learning-challenges.md` describes the first daily challenge experience at a product level.
- `docs/PRODUCT_SENSE.md` explains how to make product decisions when requirements are underspecified.
- `PLANS.md` defines ExecPlan requirements for complex features and significant refactors.
- `docs/exec-plans/` contains living implementation plans and follow-up planning notes.

## Architecture and Implementation

- `ARCHITECTURE.md` defines the monorepo boundaries and current runtime architecture.
- `FRONTEND.md` defines Angular component, Bootstrap, and frontend check conventions.
- `docs/DESIGN.md` summarizes visual and UX direction without duplicating frontend implementation rules.
- `docs/design-docs/index.md` explains design docs.
- `docs/design-docs/core-beliefs.md` records the repo's agent-first engineering beliefs.

## Quality, Reliability, and Security

- `docs/QUALITY_SCORE.md` is a lightweight rubric for evaluating changes.
- `docs/RELIABILITY.md` records repeatable run, test, migration, and workflow expectations.
- `docs/SECURITY.md` documents current auth and data-handling expectations.

## Supporting Material

- `docs/generated/README.md` explains where generated documentation belongs.
- `docs/references/README.md` explains how to handle stable external references.

Keep this index current when adding new durable docs.
